# 第2章 快速入门 & 第3章 操作指南 写作规范

## 第2章 快速入门

### 定位
面向零基础新手用户，提供"低门槛、高落地性"的产品入门流程，聚焦**快速创建核心资源 + 验证基础功能**。

### 核心结构
每个操作子章节（如 2.1 快速配置XXX）包含以下固定段落：

| 段落标题 | 字号 | 必选/可选 | 写作要点 |
|----------|------|-----------|----------|
| 操作场景 | H1 | **必选** | 明确业务场景、操作目标、适用人群与核心价值；介绍操作流程总览 |
| 前提条件 | H1 | **必选** | 明确操作前必备条件，避免因缺失前提导致失败 |
| 操作步骤 | H1 | **必选** | 按总体流程拆解，每步聚焦单一目标；可设H2子段落标题；各子段步骤从1重新编号，使用有序列表 |

### 操作步骤写作规范
1. 每个步骤采用 `步骤N：{步骤名称}` 格式
2. 步骤内使用有序列表（1. 2. 3.）
3. 操作描述简洁、可落地，避免复杂逻辑
4. 控制台操作需明确路径：`页面 → 导航 → 按钮`
5. 可按需提炼每组操作步骤做H2子节段落标题

### 写作风格要求
- **通俗化**：避免技术术语堆砌
- **推荐值导向**：配置项给出固定推荐值，无需用户决策
- **精简**：仅保留核心步骤，隐藏默认配置

## 第3章 操作指南

### 定位
面向全层级用户，覆盖产品**全场景任务 + 全配置选项**，提供**步骤化、可落地**的操作指引。

### 章节结构
```
3 操作指南
├── 3.1 业务风险提示通用写法（必选）
├── 3.2 操作指南总览（可选）
├── 3.3 使用限制总览（可选）
├── 3.4 功能特性1
│   ├── 3.4.1 创建XX
│   ├── 3.4.2 启停/重启XX
│   ├── 3.4.3 变更XX配置
│   └── 3.4.4 释放XX
├── 3.5 功能特性2
│   └── ...
└── ...（更多功能特性）
```

### 3.1 业务风险提示通用写法

#### 场景一：对业务有影响

```markdown
操作场景
当存在 [具体业务诉求] 时，可执行 [操作名称] 操作。

注意事项
该操作会产生 [直接结果]，这将影响业务正常运行，具体受影响的业务为 [列举范围]，预计影响时长为 [预估时长]。建议在 [适宜执行条件或时段] 前提下执行本操作。如非必要，请谨慎执行本操作。
```

#### 场景二：对业务无影响

```markdown
操作场景
当存在 [具体业务诉求] 时，可执行 [操作名称] 操作。

注意事项
该操作不会影响其他业务正常运行。建议在 [适宜执行条件或时段] 前提下执行本操作。
```

### 3.2 操作指南总览（可选）

| 列名 | 内容 |
|------|------|
| 功能特性名称 | 产品核心功能模块 |
| 核心操作目标 | 该模块能完成什么 |
| 对应操作章节 | 跳转链接 |
| 操作难度 | 低 / 中 / 高 |
| 预估耗时 | 时间范围 |

### 3.3 使用限制总览（可选）

| 限制类型 | 说明示例 |
|----------|----------|
| 资源配额限制 | 单地域实例数量≤50台 |
| 权限限制 | 创建/释放需特定权限 |
| 配置依赖限制 | 变更规格需实例已关机 |
| 网络依赖限制 | EIP仅支持同地域绑定 |
| 操作频率限制 | 重启频率≤5次/小时 |

## 3.4+ 功能特性章节 — 子操作文档模板

### 适用范围
每个功能特性下的单一操作落地子章节（如创建XX、启停XX等）。

### 固定段落体系

| 段落 | 必选/可选 | 写作目的 |
|------|-----------|----------|
| 操作场景 | **必选** | 业务背景、适用场景和核心价值 |
| 前提条件 | **必选** | 备备条件、约束限制、前置操作；未满足时提供表格解决方案 |
| 操作步骤 | **必选** | 流程化拆解，每步单一目标，支持控制台+API/CLI多渠道 |
| 验证方法 | **必选** | 简单高效可量化的结果验证，形成操作-验证闭环 |
| 回退方法 | 可选 | 回退/修正方案及适用场景 |
| 后续操作 | 可选 | 业务落地延伸指引，关联其他功能操作 |

### 各段落详细规范

#### 操作场景（必选）
1-2句话说明：
- 什么时候需要做这个操作
- 这个操作能达成什么效果
- 适用对象是谁

#### 前提条件（必选）
- 列出所有前置条件（账号状态、权限、已创建资源等）
- **关键**：针对未满足前提的情况，必须提供解决方案表格

```markdown
| 序号 | 情况 | 操作方案 |
|------|------|----------|
| 01 | {情况A} | {解决方案A} |
| 02 | {情况B} | {解决方案B} |
```

#### 操作步骤（必选）
- 采用 `步骤N：{步骤名称}` 格式
- 步骤内有序列表
- 每步明确：**操作入口 + 配置选项含义 + 执行结果**
- 支持多渠道：控制台（主流）、API/CLI（辅助）

#### 验证方法（必选）
提供至少一种验证方式：
1. 控制台可视化验证（推荐优先）
2. 命令行/工具验证
3. API调用验证

#### 后续操作（可选）
适用于创建类操作，指引用户后续的业务部署方向。

> 注意：创建XXX、登录XXX、初始化XXX等操作完成后往往不具备实际业务意义，此段落用于指引后续方向供用户参考规划。
