# 第1章 产品简介 写作规范

## 1.1 产品概述

### 定位
面向所有用户（含零基础用户、研发/运维人员、决策层），建立产品基础认知，回答"产品是什么、为什么选、怎么用、怎么用得合理"等核心入门问题。

### 必选段落

#### 产品定义与核心价值（必选）
- **写作目的**：让用户一句话搞懂"产品是什么"
- **核心内容**：
  - 基础定义：明确产品名称（含英文全称及缩写）、所属服务层级（IaaS/PaaS/SaaS）、核心功能定位
  - 核心价值：提炼1-2个核心优势，类比生活化场景
- **写作示例**：
  > 云服务器（Cloud Virtual Machine，CVM）是腾讯云提供的 IaaS 级别云计算服务，核心是为用户提供弹性伸缩的计算资源，免去硬件采购前期准备，实现计算资源即开即用。

#### 前置知识铺垫（可选）
- **适用条件**：适配复杂产品时使用
- **核心内容**：列出阅读前提的基础概念（无需展开解释）

#### 核心优势（必选）
- **写作目的**：向用户传递产品竞争力
- **核心内容**：分点列出3-6个核心优势，每个优势包含**特性+价值**
- **推荐维度**：
  - 功能特性（如支持多架构、多实例类型）
  - 易用性（如分钟级交付、多渠道操作）
  - 成本优化（如多种计费方式）
  - 稳定可靠（如可用性SLA数据）
  - 安全保障（如多层安全机制）
  - 弹性灵活（如按需扩缩容）

#### 产品核心架构（可选）
- **适用条件**：组件复杂的产品
- **核心内容**：列出核心功能组件，可搭配简单架构图

#### 使用方式（必选）
- **写作目的**：告诉用户通过哪些方式可以使用产品
- **核心内容**：分点列出多种使用渠道（Web控制台、API、SDK、CLI、移动端），每个渠道简要说明核心操作场景

#### 使用建议（可选）
- **核心内容**：从2-4个关键维度给出建议
- **推荐维度**：地域/可用区选择、高可用性保障、网络规划、安全方案

## 1.2 相关概念

### 定位
产品的"术语字典+认知桥梁"，清晰定义全链路核心术语、组件及技术概念。

### 整体结构逻辑
按 **基础通用类 → 核心功能类 → 关联组件类 → 易混淆类** 的顺序分类。

### 分类原则
- 按产品功能模块划分（计算类、存储类、网络类、安全类）
- 分类名称采用"XX类概念"格式
- 每个分类下概念按"核心程度"排序

### 单个概念写作框架

| 要素 | 写作目的 | 核心内容 |
|------|----------|----------|
| 概念名称 | 明确术语标识 | 中文全称 + 英文全称（及缩写）|
| 核心定义 | 解释"是什么" | 1-2句通俗语言，不涉及复杂原理 |
| 关键属性/特征 | 补充核心信息 | 列出2-3个核心属性（规格、生命周期、关联关系）|
| 关联场景/操作 | 建立概念与实用的关联 | 说明对应的产品功能和操作场景 |

### 易混淆概念区分（按需）
采用**表格对比**形式，从以下维度区分：
- 定义差异
- 核心区别
- 适用场景

## 1.3 监控指标

### 定位
系统梳理产品核心监控指标体系，帮助用户实时掌握产品健康状态。

### 监控指标表设计

| 字段名称 | 写作要点 |
|----------|----------|
| 指标类型 | 产品功能模块分类（计算类、存储类、网络类、安全类）|
| 指标/事件ID | API调用唯一标识，与API文档保持一致 |
| 指标名称 | 中文名称 + 英文标识，与监控控制台显示一致 |
| 单位 | 行业通用标准单位（%, Mbps, 次/秒, ms）|
| 指标描述 | 通俗解释含义、衡量对象及统计逻辑 |
| 正常范围 | 推荐的正常运行阈值 |
| 异常影响 | 超出正常范围的业务后果 |

### 必选段落

#### 按标标查看方式（必选）
分渠道说明查看方法：
- 产品控制台（可视化图表）
- 云监控平台（多实例对比、自定义报表）
- API/命令行工具（自动化集成）
- 移动端App（随时随地查看）

#### 异常阈值参考与处理建议（必选）
按指标类型分类，给出异常分级阈值及排查方向：

| 字段 | 内容 |
|------|------|
| 指标类型 | 计算类/存储类/网络类等 |
| 异常级别 | 警告/严重 |
| 阈值范围 | 具体数值范围 |
| 处理优先级 | 高/中/低 |
| 排查方向 | 可执行的操作建议 |

## 1.4 与其他云产品的关系（可选）

### 定位
帮助用户明确本产品与其他云服务的依赖、互补及集成关系。

### 分类逻辑
按优先级从高到低排列：**核心依赖服务 → 功能互补服务 → 可选集成服务**

每个云产品需明确：
| 维度 | 说明 |
|------|------|
| 服务名称 | 被依赖的云产品名称 |
| 依赖类型 | 核心依赖/功能互补/可选集成 |
| 关联逻辑 | 为什么需要该服务 |
| 应用场景 | 什么业务场景需要 |
| 配置要点 | 配置注意事项和约束 |

---

## 1.5 应用场景

### 定位
以简洁直观的方式呈现产品核心适配场景，帮助用户快速匹配自身业务需求。

### 结构逻辑
按 **通用基础场景 → 垂直行业场景 → 特殊需求场景** 排序

每个场景以"场景名称"作为二级标题，用1-3句话阐述：
- 场景核心特征
- 业务需求
- 产品适配点
